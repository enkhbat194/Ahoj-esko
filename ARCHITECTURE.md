## Target data flow
Canonical outcome/lexicon/form/grammar/phonology/utterance data → versioned lesson definitions → one reusable exercise runtime → shared UI components → per-skill learner events → unified review scheduling. Separate asset catalog indexed by exact text revision, locale and speaker role. No duplicated runtime for every lesson. Keep reader and lesson-specific behavior as adapters to shared identity/progress rather than erasing necessary differences.
Proposed canonical record fields: stable ID; status (draft, reviewed, approved); provenance and license; prerequisites; CZ/MN context; exact form IDs; skill and scoring mode; audio IDs; explicit allowed model responses. No claim schema implemented. Migrations must retain progress and old IDs or explicitly map them.

## Audio policy
Retain private archive; use approved exact-text assets after QA. Reader male voice including dialogue/current-word help; lesson male/female by consistent natural roles; dictionary individual approved spoken-form clips. No public archive, private IDs or credentials. No mass regeneration, new charges or storage changes without owner authorization. Browser Czech TTS is labeled fallback, not approved audio. STT transcript is not pronunciation score. Reader current-word example must only play stuck word; advance on acceptable recognition or explicitly assisted path with no false mastery.
